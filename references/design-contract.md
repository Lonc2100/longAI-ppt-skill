# DESIGN.md 规范与风格扩展

## 建立与定版时机

在用户确认页数及 ASCII 逐页主标题、必现文字之后，寻找可视参考并选定主方向。此时形成本次项目的 DESIGN.md 初稿，指导素材搜集；不要等素材全部取得才写，也不要把尚未验证的素材适配提前定死。

初稿区分已确定规则、素材要求和待验证项。例如可先确定摄影占比、排字气质和色彩角色，再用实际照片验证裁切、叠字位置与对比度。随后用实际素材制作代表页，与参考并排比较；验证后更新并定版同一份 DESIGN.md，作为全稿依据。更换素材影响设计时回写相关规则；后续有效规范始终只有一份。

## 格式与完整内容

沿用 [Google Labs DESIGN.md 规范](https://github.com/google-labs-code/design.md/blob/main/docs/spec.md) 的结构。2026-10-03 核对时规范为 alpha，YAML frontmatter 在上游为可选；本项目选择使用 **YAML 参数＋Markdown 设计理由与使用规则** 两层。采用的字段遵循类型与引用语法，不能自造一组字段后宣称完全符合上游 schema。

YAML 记录适用的 `name`、`version`、`description`、`colors`、`typography`、`rounded`、`spacing`、`components`。颜色写明确值；字体属性包含字体、字号、字重、行高、字距及必要字体特性；组件可通过 `{colors.primary}` 等路径引用已定义参数。不适用的字段说明原因，未知值不补造精确数字。

正文按下列主体顺序组织；不适用部分可以说明省略原因，不把通用格式变成无意义的填表：

| 章节 | 应记录的设计判断 |
| --- | --- |
| Overview | 视觉定位、受众、气质、主参考、核心特征与适用范围 |
| Colors | 背景、表面、正文、强调与状态的颜色职责及使用限制 |
| Typography | 字体与回退、字级、字重、行高、字距、阅读宽度及使用场景 |
| Layout | 画布、栅格、边距、安全区、间距、对齐、构图与密度 |
| Elevation & Depth | 阴影、叠压、透明度、空间层次；平面设计如何建立层级 |
| Shapes | 圆角、边框、线条、箭头及形状语言 |
| Components | 分页、对白、标注、表格等所用组件的样式、尺寸与状态 |
| Do's and Don'ts | 必须保留的设计特征、明确禁用处理及视觉检查要求 |

演示稿还需补充以下**项目扩展**，可写为对应章节的小节或附加说明；不冒充上游原有固定字段：

- 图像与素材：摄影／插画方向、主体关系、光线、比例、裁切、调色和背景处理；实际素材来源与许可清单可链接 sources.md，避免重复维护。
- 图表与信息表达：数值比例、单位、标签、重点突出、状态与连线；不能用装饰误导数据含义。
- 动效与播放：入场、分拍、转场、回退、最终状态与减少动态效果。
- 逐页变化与整套节奏：各页承担何种作用，何时用大字、摄影、对照、图表；保持统一但不机械套版。
- 可读性与适配：文字对比、长标题、文字密度、字体缺失、窗口缩放和异常情况处理。
- 参考与待定项：来源、借鉴特征、项目调整、验证结果、用户取舍与尚待验证内容，区分观察事实和主动设计选择。

来源说明：[Refero DESIGN.md 模板](https://styles.refero.design/design-md/design-md-template)同样要求将真实参考、项目选择与未知项区分。这里列出的演示稿扩展是本 Skill 的项目要求。

## 内置风格与项目规范的区别

一个风格一个目录：DESIGN.md（设计判断）、theme.css（变量和表达）、至少三种真实页面样张（封面、正文、复杂信息）。样张可以位于 examples/ 并在目录中链接。

新增或修订风格应覆盖上述适用规范与扩展，不能只留配色、字号和几个气质词。当前 0.1.0 简化示例保留作原型，不视为新版规范的完整示范；后续视觉修订须按此要求对照原优秀成品重新验证。

catalog.json 登记唯一 id、名称、用途、规范路径、主题文件路径和样例路径；所有路径局限于包内。初始化脚本从目录读取，不写死风格列表。

库规范用可迁移原则；每次项目规范增加真实标题、受众、页数、内容密度、具体素材和取舍。案例的事实判断与日期留在案例。一个项目采用一个主风格，必要的强调页仍共享色彩和字级。

验收：用新内容渲染代表页，检查中文标题、表格/流程、长文本和无图版本。新方向经过视觉检查才标可用。换配色不足以构成一个新风格。
